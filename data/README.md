# 小番茄数据与探索性模型

## 来源与可追溯性

`tomato_observations.json` 由 `scripts/build_tomato_data.py` 生成，记录原始文件名和 SHA256。

- `小番茄硬度数据.csv`：719行、20个温度/天数组，两指标各465个非空读数，共930读数，形成39个非空指标组均值。行数不是果实数量，两个指标未确认逐果配对；n是该指标有效读数数。
- `小番茄货架期数据.xlsx`：`五个重复组`与`百分比换算组`。原有比例与五组计数之和/125核对一致，但实验判定口径待确认，不能直接命名为腐烂率。仅使用原有比例单元格，不从计数补填比例空白。
- 重建还需 `拟合补全_模型估计/最终补全参数.json`，其中既有软化参数仅用于低可信度情景；其SHA256也记录在生成文件中。
- 不改写原始输入，不纳入人工补全的单项读数作为实测，不处理条件归属不明的数据。

## 阈值时长

保留原有非单调比例波动，寻找首次跨越用户阈值的相邻记录，线性计算跨越时刻。非实验温度在两侧温度的跨越时刻间线性插值；任何一侧未跨越则拒绝估计。未建立统计置信区间。

默认10%是演示值。在该阈值下0/5/10/15/20/25℃总时长分别为17.625/15.75/14.5/9.5/7.25/5.25天；不代表经验证的保质期。

## 硬度

实测条件直接返回原始有效读数组均值与n。同温度有前后实测时进行时间线性插值；非实测温度不估计。

5℃只有第0天实测，后续至14天为假设软化情景；Q10=2和第7天冷害拐点均为建模假设，并非已获文献或本批实验验证。敏感性范围综合Q10、软化速率、冷害强度变动，非95%置信区间。10℃由0/3天趋势指数外推至9天，并标为低可信度情景。其他超出支持范围的硬度拒绝估计。

全局软化模型的验证不足以可靠识别温度响应，不将其包装成已验证的温度规律。所有估计的目标时点实测n=0，并单列支撑记录；不可把估计当新增实测重复。硬度不修正阈值时长。

本模型不含成熟度、湿度、包装、病原菌与食用安全判定。须确认比例口径、实际失效标准并开展独立验证后，才能考虑作为正式货架期模型。


## 温度＋实测硬度反推模式（2026-10-27）

网页采用 `tomato_firmness_stage_matching`：仅使用本JSON的实测硬度组均值折线反解阶段，然后用参考总时长减去阶段。非单调时保留全部解；单点基线（5℃）不推算，范围外不外推；非实测温度只在相邻温度共同时间覆盖内插值。两种硬度不换算，不使用旧情景曲线反推。

参考总时长仍依赖未验证的10%比例演示终点，因此结果是探索性、非食品安全期限；候选范围也不是置信区间。硬度与比例未证明逐果配对。旧版天数模式和其情景说明仅适用于显式提交 `storage_days` 的兼容API/CLI，不再用于网页。


## 整数检测值自动换算FT11（当前网页）

网页只接收40–90的整数检测值，沿用项目既有公式 `FT11 = (检测值 - 32.714) / 0.14`，实时展示g·mm⁻²映射值。后端再次验证整数范围并独立换算。用于阶段匹配的整数实测组均值也采用同一映射，保留原始整数均值；因为线性变换单调，匹配天数与原整数尺度一致。禁止将独立g/mm列冒充FT11的g/mm²，也不使用樱桃货架期模型。映射值不是新增实测、不是经独立验证的小番茄仪器标定。旧尺度API兼容仅限显式指定指标。
